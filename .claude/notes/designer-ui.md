# デザイナーの画面構成（メニュー・ツールバー・画面一覧）と、定数・起動フォームの実行時連携（2026-10-09）

## 画面構成
- **2段表示**（`index.html`）: 1段目`#menu-row`（メニュー: ファイル／編集／表示／プロジェクト／設定／ヘルプ）、2段目`#toolbar`（よく使うボタンだけ: 新規・開く・保存｜元に戻す・やり直し｜実行・停止・エラー・コンパイル｜テーブル・検証(V)｜AI設定・ヘルプ）。以前は1行にメニューとボタンが全部並び、横幅が足りなくなった。
- **メニューの割り当て**: プロジェクト＝プロジェクト情報・アプリイベント・定数・テーブル管理・バリデーション定義・拡張ランタイム／設定＝AI接続設定・学習ノウハウ・クラウドインフラ設定・フォント設定／表示＝グリッド・スナップ・デバッグ表示／ヘルプ＝ヘルプ(F1)・バージョン情報。設定系ボタンをツールバーに戻さないこと（増えると同じ問題になる）。メニューに無いボタン行は、よく使うものだけ（新規・開く・保存・元に戻す・やり直し・実行・停止・エラー・コンパイル）。例外として、テーブル・検証(V)・AI設定・ヘルプは、メニューにもあるがボタンも残している（ユーザー要望）。
- **新しいメニュー項目を足す時**: `toggleMenu('id', event)`はクラス名で開閉するため、メニュー側は項目を足すだけでよい。ヘルプ・ユーザーガイド・`help/*.md`のsummary（AI検索のキーワード）にある操作説明（「ツールバーの○○」「メニュー［△△］→」）も直すこと。
- **画面一覧パネル**: 左側、ツールボックスの下（`#form-panel`、`vja-save.js`の`buildFormSelect`が一覧を作る。テンプレートは`templates/form-list.html`）。以前の「画面:」ドロップダウン（`fdd-*`）は廃止。件数が増えても使えるよう、検索欄・ドラッグ並べ替え・↑↓ボタン・ダブルクリックで名前変更を持つ。並べ替えは`forms`配列の並びを変える（`formMoveTo`）。選択中の画面は番号でなく`id`で追従し、Undo（スナップショットが`forms`と`curFormIdx`を含む）に対応。絞り込み中はドラッグ無効（並びの混乱防止）。
- **ツールボックスと画面一覧の境**: `#resize-form-panel`をドラッグして画面一覧の高さを変える（`startFormPanelResize`、`clampFormPanelH`）。最小100px、ウィジェット一覧が約60px残る上限。ウィジェット一覧（`.tool-grid`）が狭くなるとスクロール。高さは`ui-config.json`の`formPanelH`（既定240）に保存（`saveUiConfigRequest`/`loadUiConfigRequest`の引数にも追加）。
- **定数エディタ**: 全体（グローバル）とフォームの定数を1つのモーダルのタブで編集（`openConstEditor(tab)`、`vja-table-validation.js`）。両方の編集内容を`CONST_MODAL.rowsG/rowsF`に持ち、保存で一度に反映。フォームのタブでは全体と同名の行に注意を出す。`openFormConstEditor`は、`bridge.ts`のテスト用一覧が名前で参照するため、フォームのタブを開く入口として残している。

## 実行時に効いていなかった2つの不具合（最初のコミットから）
- **定数が`vja.const.get`で常に既定値(null)だった**: `vja.const.init()`を呼ぶ箇所がソースのどこにも無かった（履歴にも一度も無い）。AIは`vja.const.get('名前')`を使うコードを生成していたので、実行すると常にnullだった。修正: `buildFormHtml`（`bun/index.ts`）が各フォームのHTMLに`vja.const.init(全体の定数, そのフォームの定数)`を埋め込む（`bun-utils.ts`の`buildConstInitScript`。`</script>`等はエスケープ）。全体の定数は`_updateProjectData`で`_currentProjectConstants`に保持。コンパイルも同じ`buildFormHtml`を使うので両方に効く。
- **起動フォーム（★）が実行時に効かず、常に先頭のフォームだった**: `bun/index.ts`と`standalone-index.ts`が`forms[0]`を起動していた（`startFormId`はBun側に渡っていなかった）。修正: `pickStartForm`（`bun-utils.ts`）で★のフォームを選び、無ければ先頭。実行用データ（`_getProjectData`）に`startFormId`を追加。★を押したら画面一覧とプロパティパネル（「全体に反映/トップに合わせる」）が即時更新される。
- **教訓**: 「画面で設定できる」と「実行時に効く」は別。設定項目を足したら、保存→実行ウィンドウ→コンパイル後アプリまで、値が届くことを実機で通して確認する（どちらも、設定画面とAI生成のコードは動いていたため気づけなかった）。

## AI設定が無効なときの共通の扱い（2026-10-09）
- 全てのAI機能（イベントのAI生成・テーブル・バリデーション・画面デザイン・拡張ランタイムのAI向け説明・ヘルプの質問）は、`ensureAiEnabled(resume?)`（`vja-ai-config.js`）で有効か確認する。無効なら「設定画面を開きますか？」→「はい」で、**今のモーダルを閉じずに**その上（`modal-layer-1`）へAI設定を重ねて開く（`openAiConfig({ overlay: true, resume })`）。反映・キャンセルで重ねた層だけを閉じるので、元の画面（入力中の内容を含む）にそのまま戻る。呼び出し側は、falseが返ったら処理を中断する。
- `resume`を渡すと反映後に1回だけ呼ばれる（キャンセルでは破棄）。ヘルプは、入力欄に残した質問を自動で実行する（`() => helpAsk()`）。他の機能は、AI生成を自動実行せず、元の画面に戻るだけ（生成は既存内容の上書きが絡むため）。
- 以前は、確認で「はい」を選ぶと`closeModal()`で元の画面を閉じてからAI設定を開いたため、反映後に元の画面へ戻れず、エディタに入力中の内容も失われる恐れがあった（ウィザードだけ`WIZARD_STATE.resumeAfterAiConfig`で戻る専用の仕組みがあった）。ウィザードは従来のまま（引数なしの`openAiConfig()`＋`resumeAfterAiConfig`）。
- AI設定画面の再描画（プリセットの切り替え・保存・削除）は`aiCfgRender()`を使う（層と続きの処理を保つ）。`openAiConfig()`を再描画に使うと、層がrootに戻るので使わないこと。
- 新しいAI機能を足す時は、`aiConfig.enabled`を自前で見ず、`if (!(await ensureAiEnabled())) return;`を使う。
