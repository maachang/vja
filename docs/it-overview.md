# VJA 導入のための確認事項（IT 担当向け）

社内に VJA を導入する際に、IT 担当の方が最初に確認したい点を、事実ベースでまとめた資料です。コードで確認できたことだけを書き、確認できていない点は「未確認」と明記しています。

## 1. 何をするツールか

- **VJA（Visual JavaScript for AI）** は、フォームにウィジェットを配置して、小さな社内アプリを作るデスクトップ開発ツールです（Electrobun / Bun 製）。
- 作ったアプリは、実行ファイルとして配布できます。サーバーは不要で、データ（SQLite）は手元の PC に保存されます。
- AI は、画面やイベントコードの下書きを作るために使います。ローカル LLM（外に出ない）でも、クラウド API でも動きます。
- 向く用途・向かない用途は、[VJA の位置づけ](positioning.md) を参照してください。

## 2. 通信先の一覧

| 通信 | 宛先 | いつ発生するか |
|---|---|---|
| AI（ローカル LLM） | 設定したエンドポイント（既定 `http://localhost:8080`） | AI 機能を使ったとき。`localhost` なら外に出ません。社内の別ホストを指定すれば社内通信です |
| AI（クラウド） | `https://api.openai.com/v1/chat/completions` | API キーを設定した場合の AI 機能。**キーを入れると、設定したエンドポイントは使われず、必ずこの宛先へ送られます** |
| AWS SDK の取得 | `https://cdn.jsdelivr.net/npm/@aws-sdk/…`（実行時に取得） | クラウド設定で AWS を使うとき。**バージョンは固定されていません（常に最新）**。閉域網では使えません |
| AWS API | `*.amazonaws.com` など | `vja.aws.*` を使うイベントを実行したとき |
| Slack / Chatwork / Webhook | `slack.com` / `api.chatwork.com` / 利用者が設定した URL | `vja.slack.send` / `vja.chatwork.send` / `vja.webhook.post` を使ったとき |
| 任意の URL | 制限なし | `vja.http.*` を使ったとき。**宛先の許可リストはありません** |
| 開発環境でのコンパイル | npm レジストリ、Electrobun のバイナリ配布元 | 開発者がコンパイルしたとき（依存の取得）。**配布アプリの実行時には発生しません** |

- デザイナーと実行画面が読み込むスクリプトやスタイルは、すべて同梱のファイルです（CDN、外部フォント、外部 CSS の参照はありません）。外部の CDN を使うのは、上の AWS SDK だけです。
- **自動更新、使用状況の送信（テレメトリ）、VJA 自身が待ち受けるサーバー機能は、コード上では確認できません。** ただし、基盤の Electrobun 本体の通信と、画面と本体の間の通信（ローカルの WebSocket とされています）の待ち受けアドレス・ポートは、確認できていません（未確認）。

## 3. データの保存場所と、配布物に含まれるもの

| 対象 | 場所 | 備考 |
|---|---|---|
| プロジェクト | `.vjaproj` ファイル（利用者が保存した場所） | JSON 形式。画面・テーブル定義・イベントコード・設定を含みます |
| 設定の保存先 | `~/.vja-designer/` | 前回のフォルダ、UI 設定、AI の「プロジェクト共通」プリセット（`ai-global-presets.json`） |
| 作業・コンパイル出力 | `~/.vja-apps/VJAFormDesigner/` | デザイナーから実行したときのデータベース、コンパイル出力 |
| 配布アプリのデータ | アプリのフォルダ内の `db/app.db`、`logs/` | 配布アプリごとに保存されます |
| ログ | `logs/app.<日付>.log` | 既定のレベルは info。**AI へ送るプロンプトの本文はログに出ません**（長さなどのみ）。debug レベルに上げると、AI の返答の全文が残ります |

### 秘密情報の扱い

- **AI の API キー**: 保存時に暗号化されます（AES-GCM）。ただし、鍵（固定パスフレーズ）がソースコードに含まれ、鍵の元になる合言葉も同じファイルに入るため、**難読化にとどまります**。ファイルを渡すと、VJA のソースを知る人は解読できます。
- **クラウドの認証情報**（AWS のアクセスキーなど）: 同じ方式で暗号化されます。強度も同じです。
- **配布アプリ**: プロジェクト情報の設定で、配布アプリへコピーする `project.vjaproj` から、秘密情報を除けます（元のプロジェクトのファイルは変わりません）。
  - 「コンパイル時に AI の API キーを配布アプリへ含めない」: **既定は ON** です。
  - 「コンパイル時にクラウドの認証情報を配布アプリへ含めない」: **既定は OFF** です。ON にすると、認証情報の値を消し、全項目を「アプリ側入力」に切り替えます。配布先の PC では、`~/vja/credential.json`（または `.yml` / `.yaml`）から読みます。
  - クラウド設定で、項目ごとに「アプリ側入力」を ON にした場合も同様に、その項目の値はプロジェクトに保存されません（以前の版で値を入力してから ON にした場合は、保存し直すと値が消えます）。
  - **クラウドの認証情報を含めたまま配る場合は、権限を絞ったものだけを設定してください。**
- 古い版で保存したプロジェクトは、キーが平文のままの場合があります。開いて保存し直すと、暗号化されます。

## 4. AI 接続ごとのデータの流れ

| | ローカル LLM | クラウド API（OpenAI） |
|---|---|---|
| 送信先 | 設定したエンドポイント（既定は同じ PC の `localhost`） | `api.openai.com` |
| 送るもの | フォーム定義、テーブル定義（スキーマ）、イベントの YAML・JS コード、利用者が書いた自然文の要望、システムプロンプト | 同左 |
| DB の実データ | 送信する実装は確認できていません | 同左 |
| 外に出るか | 出ません（エンドポイントが同じ PC か社内の場合） | 出ます |

- AI の機能は、すべて同じ経路（OpenAI 互換の `/v1/chat/completions`）で呼び出します。ヘルプの質問応答も同様です。
- 「DB の実データを送る実装は確認できていない」というのは、プロンプトを組み立てる全箇所を精査したという意味ではありません。機密性の高い用途では、ローカル LLM の利用を推奨します。

## 5. 使える API と制限

- `vja.*` の主なカテゴリ: `db`、`widget`、`form`、`const`、`session`、`validate`、`io` / `file` / `dir`、`http`、`crypto`、`notify` / `ui`、`aws.*`、`slack` / `chatwork` / `webhook`、`log`、`app`（ダイアログ）。
- **イベントコードは任意の JavaScript として実行されます。** サンドボックスや許可リストはありません。AI が生成したコードには、API 名の確認（未知の API の検出）と構文チェックを行いますが、手で書いたコードや、確認を通ったコードの意味的な正しさまでは保証しません。
- **ファイル操作にパスの制限がありません。** 読み書き・削除の対象は、実行する利用者の権限の範囲全体です（「ローカルアプリ」という前提で、設計上考慮していません）。
- ユーザーコード向けの API に、外部プロセスを実行するものは、確認できませんでした。
- したがって、**信頼できる作成者のプロジェクトだけを、実行・配布してください。** 受け取ったプロジェクトファイルは、実行すると、その中のコードが動きます。

## 6. 配布・更新

- 配布アプリは、Electrobun と同梱の Bun（バージョンは固定）の実行環境を含みます。
- 更新は、プロジェクトを開発環境でコンパイルし直して、配り直す形です。ランタイムのセキュリティ更新を追う仕組みは、まだ整っていません。
- **コード署名の設定は、ありません**（macOS の署名・公証と、Windows の署名は、未整備です）。OS の警告が出ることがあります。
- 開発環境でのコンパイルには、インターネット接続（npm と、Electrobun のバイナリ取得）が必要です。

## 7. 既知の制限と未確認の点

**既知の制限**
- SQL インジェクション対策は最小限で、パストラバーサル対策もありません（ローカルアプリのため、あえて行っていません）。
- 暗号化は、前述のとおり難読化です。
- 実機で動作確認済みのクラウド連携は、AWS の S3 と STS、Slack の Web API 方式だけです。ほかのサービス（Chatwork、汎用 Webhook、Slack の Webhook 方式、S3 以外の AWS）は、単体テストまでで、実環境での確認は未実施です。

**確認できていない点（未確認）**
- Electrobun 本体の通信（更新の確認など）と、ローカルの待ち受けアドレス・ポート。
- Windows のコード署名。
- ログファイルの自動削除（ローテーション）の有無。
- プロンプトを組み立てる全箇所での、DB の実データの混入の有無。
