# VJA の位置づけ

VJA は、**ローカル LLM の制約（小さいメモリ・短い文脈・遅い推論）を前提に、AI の仕事を狭く切り出した、小さな社内アプリ向けの開発ツール**です。AI が下書きを作り、人が目と手で仕上げます。

## 向いている用途・向いていない用途

| 向いている | 向いていない |
|---|---|
| 数画面〜数十画面の社内ツール・業務アプリ | 大人数・大規模で、専任チームが保守するシステム |
| サーバー運用や公開の審査を避けたいローカルアプリ | Web 公開が前提のサービス |
| 新人教育・VBA 経験者の次の一歩 | Git でのコード単位のレビューが必須の開発 |

外部サービス（S3 など）との連携は、専門の担当者が管理する構成を前提にしています。VJA は利用側にとどまります。

## 強み

1. **ローカル LLM の制約を前提に設計**: 標準モデルは非推論の 7B クラス（qwen2.5-coder-7b）。AI への依頼は「1 イベント＝1 問い合わせ」で完結し、出力の形を決め、機械で検証・補正します。ヘルプの質問応答も、7B で成立するよう「一覧から選ぶ」ではなく「1 件ずつ採点する」聞き方にしています。
2. **費用が極小**: 7B 前提なので、低価格のクラウドモデルでも動きます。1 回の生成は 0.1 円前後、中規模アプリを一通り作っても数円程度が目安です（コスト試算は README 参照）。
3. **人が確認できる大きさのコード**: 構造が画面→ウィジェット→イベントと小さく分かれ、1 回の生成は数十〜数百行です。巨大なソースを作らないので、人が読んで確認できます。YAML（意図）と生成されたコードを並べて見られます。
4. **人が仕上げる**: VB6 のようにウィジェットを手で置けます。AI が作った画面・YAML も、ふつうのフォームとして編集できます。細かな座標の調整は、人の手のほうが速く正確です。
5. **生成から修正までが一貫**: ウィザード→画面→イベント→実行。実行時に例外が出たら、エラー一覧から「AI で修正」を呼べます。
6. **ローカルアプリ**: サーバー運用・公開の審査・依存モジュールの追跡が要りません。外から入る攻撃の面が小さく、小さな社内アプリではリスクも運用の負担も小さく済みます（負担の種類は「実行ファイルの配り直し」に変わります）。
7. **新人教育・登竜門に向く**: 画面を作る→イベントを生成→動かして直す、という流れで、結果が目に見えます。身につくのはイベント・DB・検証・エラー対応という考え方です。

## 難点と限界

- **覚えることが多い**: VB6 と同じく「道具を覚える」型です。ウィザード、ヘルプ（AI 質問応答）、サンプルで入口の負担を下げていますが、手軽さは売りにしていません。
- **7B の限界**: 選ぶ・判断する仕事に弱く、定型の仕事に向きます。生成コードの意味的な正しさは保証できません。複雑な設計・デバッグ・長いコードの理解には向きません。
- **再生成すると手直しが消える**: 画面デザインの再生成は、今のウィジェットを置き換えます。フォームから YAML への書き戻しは、画面デザインにはまだありません。
- **Git で管理しにくい**: `.vjaproj` は整形なしの 1 行 JSON で、差分が読めず、複数人でのマージもできません。
- **配布・更新・保守**: コンパイルした実行ファイルにランタイムが同梱され、更新はビルドし直して配り直します。

## ローカル LLM とクラウド API の使い分け

- **ローカル LLM**: 機密を外に出せない、オフラインで使いたい、すでに適当な PC がある場合。売りは「安いから」ではなく「外に出ないから」です。
- **クラウド API（低価格モデル）**: 手軽さを優先する場合。PC の性能を問いません。費用だけを理由にするなら、ハードを買うよりクラウド API のほうがはるかに安く済みます。

## 誇張しない姿勢

「AI があれば誰でも大きなアプリが作れる」とは言いません。できること・できないことを、そのまま示します。
