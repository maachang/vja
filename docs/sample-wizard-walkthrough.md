# 🧙 サンプルウォークスルー: ウィザードでプロジェクトを立ち上げる

このドキュメントは、VJA の「プロジェクト新規作成ウィザード」機能で、思いつきの日本語だけからプロジェクトの雛形（複数フォーム＋DBテーブル）を一括生成する流れを、実際の画面遷移に沿って説明するものです。

> ⚠️ 本ドキュメントは機能の**使い方の流れ**を説明するためのイメージ例であり、[サンプルウォークスルー: ログイン・ユーザ登録機能をほぼノーコードで作る](sample-login-nocode.md)のように「この通りの出力が必ず生成される」ことを保証するものではありません。AIの出力は依頼文・使用モデル・プロジェクトの状態によって変わります。ウィザードそのものの詳しい仕様は[ユーザーガイド](user-guide.md#2-プロジェクトの作成保存読み込み)を参照してください。

---

## ウィザードが向いているタイミング

- 「思いついたアプリの構想はあるが、どの画面から作ればいいか決めていない」ときの取っ掛かりとして
- 既存プロジェクトを流用せず、まっさらな新規プロジェクトを素早く立ち上げたいとき

ウィザードは**プロジェクトの雛形（フォームの骨組み）を作るだけ**の機能です。画面遷移の実装やDBテーブルのカラム構成は対象外で、生成後に他のAI雛形生成機能（イベントYAMLドラフト・テーブルAI生成等）と組み合わせて仕上げていく前提です。

---

## 1. ウィザードを開始する

メニュー［ファイル］→［ウィザードでプロジェクト作成…］を選択します。未保存の変更があれば確認ダイアログが表示され、続けるとAI接続設定・プロジェクト情報が未設定の場合はそれぞれ入力を促されます（詳細は[ユーザーガイド](user-guide.md#🧙-ウィザードでプロジェクトを作成)参照）。

## 2. Q&A（ヒアリング）に答える

AIが1問ずつ質問を生成し、答えていきます。例えば「在庫管理っぽいものを作りたい」という漠然とした思いつきから始めた場合、次のような対話イメージになります。

> **Q1. どのような業務・用途で使うシステムでしょうか？できるだけ具体的に教えてください。**
> A1. 小さな倉庫の在庫管理。商品の入荷・出荷を記録して、現在の在庫数を確認したい。

> **Q2. ログイン機能は必要ですか？**
> （選択肢: はい / いいえ）
> A2. はい

> **Q3. 主にどのような操作を行いたいですか？（複数選択可）**
> （選択肢: 商品の登録, 入荷の記録, 出荷の記録, 在庫一覧の確認）
> A3. 商品の登録,入荷の記録,出荷の記録,在庫一覧の確認 （番号入力「1,2,3,4」でも同じ結果になります）

> **Q4. 画面数の目安はどれくらいにしますか？**
> （選択肢: 少なめ / 標準 / 多め）
> A4. 標準

質問数に決まった上限はありませんが、ある程度質問が続くと「質問数が多くなっています。『完了』で次へ進むこともできます」という案内が出ます。それでも聞き足りないと感じれば続けて構いませんし、途中で十分と感じたら**いつでも「完了」ボタン**で次に進めます。「← 戻る」で前の質問に戻って回答を直すこともできます。

## 3. 確認モーダルでフォーム・テーブル構成を確認する

「完了」を押すと、まずAIが裏側で（画面には出ない自動処理として）ヒアリング内容に近い「業務システムの骨格パターン」を1つ選びます。これは「マスタ管理系」「伝票・トランザクション登録系」「在庫・数量推移管理系」のような、テーブル構成・画面構成の型を示す社内向けの参考パターンで、今回の「入荷・出荷を記録して在庫数を確認したい」という内容であれば「在庫・数量推移管理系」が選ばれるイメージです。この骨格は、続くフォーム構成・DBテーブル候補の提案時に「一覧・登録・編集・削除・詳細画面を無闇に分割しない」等の構成のブレを抑えるヒントとして使われます。

その上で、AIがヒアリング内容から必要なフォーム構成とDBテーブル候補を提案します。

**作成予定のフォーム（イメージ）**

| フォーム名 | 表示名 | 説明 |
|---|---|---|
| LoginForm | ログイン | ログイン認証を行う画面 |
| ProductForm | 商品登録 | 商品情報を登録・編集する画面 |
| StockMoveForm | 入出荷記録 | 商品の入荷・出荷を記録する画面 |
| StockListForm | 在庫一覧 | 現在の在庫数を一覧で確認する画面 |

**DBテーブル候補（チェックボックスで選択）**

- ☑ `users` — ログイン用のユーザー情報
- ☑ `products` — 商品マスタ
- ☑ `stock_movements` — 入荷・出荷の記録

不要なテーブル候補があればチェックを外せます。テーブルはこの時点では**名前と説明のみ**が仮登録され、カラム構成はまだ作られません。内容を確認し、「生成開始」を押します。

## 4. 一括生成が実行される

まずフォームの雛形（空の画面）がまとめて作成され、「4個の画面の雛形を作成しました」というトーストが表示されます。続けて、フォームを1つずつ切り替えながら「フォーム1/4: ログイン を生成中…」のように進捗が表示され、各フォームの画面デザインYAMLドラフト生成→画面レイアウト生成が自動で進みます。

一部のフォームだけAI生成に失敗した場合でも、そのフォームだけ空のまま残り、他のフォームの生成は継続します（後で個別に「✨ YAMLドラフト」タブからやり直せます）。

## 5. 完了後の仕上げ

生成が完了すると、画面生成が終わった旨と、テーブルのカラム構成をまだ作っていない場合はその案内が表示されます。ここから先は、通常のAI雛形生成機能で仕上げていきます。

1. **テーブルAI生成**: テーブル管理の「✨ AI生成」で `products`/`stock_movements` 等のカラム構成を作成する
2. **イベントYAMLドラフト生成**: 各ボタンのクリック処理（登録・記録・一覧表示・画面遷移等）を、フォームごとに「✨ YAMLドラフト」タブから作成する（ウィザードは画面遷移を自動でつながないため、ここで`vja.form.navigate()`の指示も行う）
3. **検証（バリデーション）AI生成**: 各フォームの入力チェックルールを作成する

この後の進め方は、[サンプルウォークスルー: ログイン・ユーザ登録機能をほぼノーコードで作る](sample-login-nocode.md)で示した「画面 → テーブル → イベント → 検証」の順番がそのまま当てはまります。

## まとめ

| 作業 | ウィザードが担う部分 | 生成後に人（＋他のAI雛形生成機能）が仕上げる部分 |
|---|---|---|
| 全体構成の洗い出し | Q&Aヒアリング→フォーム一覧・DBテーブル候補の提案 | 提案内容の取捨選択（確認モーダルでの選択） |
| フォームの雛形 | 各フォームの画面デザインYAMLドラフト→レイアウト自動生成 | 配置の微調整、画面ごとの追加要望 |
| DBテーブル | 名前・説明の仮登録のみ | カラム構成（テーブルAI生成） |
| 画面遷移・業務ロジック | 対象外 | イベントYAMLドラフト生成→JS生成 |
| 入力チェック | 対象外 | 検証（バリデーション）AI生成 |

ウィザードは「白紙から要件を思い出しながら組み立てる」作業を「まず雛形を見て、気になる点を直す」作業に変える、プロジェクト立ち上げの最初の一歩を担う機能です。
