# 署名付き URL でファイルを受け渡す

VJA のアプリに、クラウドの認証情報（アクセスキーなど）を持たせずに、S3 などへファイルを受け渡す方法です。**管理側が、期限付きの URL（署名付き URL）を発行し、VJA はその URL を使うだけ**にします。

> このガイドは「想定する使い方」です。VJA 側の送受信（`vja.http.*`）は、ローカルのテスト用サーバーで動作を確認しています。実際の S3 や Azure、Google Cloud での通し確認は、まだしていません。

## 1. 役割分担

| | やること |
|---|---|
| **管理側**（クラウドに詳しい人） | バケットなどを用意し、利用者・ファイルごとの署名付き URL を発行して、配る。アクセス権限と有効期限を決める |
| **VJA のアプリ（現場）** | 渡された URL に、`GET`（取得）か `PUT`（アップロード）をするだけ。**認証情報はアプリに入りません** |

この分担なら、アプリを配っても、権限の範囲は「その URL でできること」に限られます。

## 2. 管理側がやること（一般的な方法の例）

署名付き URL は、クラウドごとに名前が違います（S3 の署名付き URL、Azure の SAS、Google Cloud の署名付き URL）。発行は、各クラウドの公式の手順で行ってください。以下は AWS S3 の例で、環境に合わせて読み替えてください。

- 取得用（GET）: AWS CLI の `aws s3 presign s3://<バケット>/<キー> --expires-in 3600` で発行できます。
- アップロード用（PUT）: AWS CLI の `presign` は GET 用です。PUT 用は、AWS SDK（例: `generate_presigned_url('put_object', …)`）で発行します。
- **ファイル名に、利用者 ID と日付を含めます**（例: `u001/2026-10-10.csv`）。1人1ファイルにすれば、衝突しません。
- 有効期限は、用途に合わせて短めにします。
- PUT 用の URL で、`Content-Type` を署名に含めた場合は、アップロード時に同じ値を送る必要があります（3 節の例を参照）。

## 3. VJA での使い方

URL は、取得と書き込みの2つに分けて、利用者ごとに用意します。VJA には、そのための関数がもう備わっています。

### ファイルを取得する（GET）

```javascript
// 管理側から渡された、取得用の署名付き URL
let url = vja.const.get('DOWNLOAD_URL');
vja.ui.loading(true, 'データを取得中...');
try {
    let csvText = await vja.http.get(url);        // CSV を文字列で取得
    let rows = vja.io.parseCsv(csvText);          // 行データの配列に変換
    vja.widget.set('tableView', rows);
} catch (e) {
    await vja.app.showDialog('取得に失敗しました: ' + e.message);
} finally {
    vja.ui.loading(false);
}
```

### ファイルをアップロードする（PUT）

```javascript
let url = vja.const.get('UPLOAD_URL');            // アップロード用の署名付き URL
let rows = await vja.db.query('SELECT * FROM daily_report');
let csvText = vja.io.toCsv(rows);                 // 行データを CSV 文字列に変換
// Content-Type を署名に含めた場合は、同じ値を headers で指定する
await vja.http.put(url, csvText, { 'Content-Type': 'text/csv' });
```

- 画像などのバイナリは、`vja.fetch(url, { method: 'GET', responseType: 'binary' })` で取得できます（`bytes()` で `Uint8Array`）。アップロードは、`body` に `Uint8Array` を渡します。
- `vja.http.*` は、HTTP のエラー（403、404 など）が返ると、例外を投げます。`try / catch` で、利用者にわかるメッセージを出してください。

### URL をアプリに渡す方法

署名付き URL は、**期限が来ると使えなくなります**。そのため、「アプリの中に、期限付きの URL を埋め込んだまま配る」運用は、続きません。次のような方法があります。

| 方法 | 向く場面 |
|---|---|
| 定数（`vja.const`）に URL を入れて配る | 期限が長い URL。全員が同じファイルを使うとき |
| 入力欄（テキスト入力）に、利用者が貼り付ける | 管理側が、都度メールなどで URL を渡す運用 |
| 管理側が用意した、共有フォルダのテキストファイルを `vja.file.*` で読む | 社内の共有フォルダがあり、管理側が URL を更新する運用 |

どれを使うかは、運用に合わせて決めてください（VJA には、決まった方法はありません）。

## 4. 注意点

- **署名付き URL そのものが、秘密情報です。** URL を知っていれば、期限内は誰でも使えます。メールや共有チャットに貼る範囲、ログに出す内容には、気をつけてください。
- 有効期限が切れると、`403` になります。「期限切れ」の場合のメッセージを、画面に出すと、問い合わせが減ります。
- アプリに入れた URL は、プロジェクトファイルや配布アプリに含まれます。**長い期限の URL を、配布するアプリに埋め込まないでください。**
- 受け渡しは、**ファイル単位**です。複数人で同じファイルを同時に書き換える、という使い方には向きません（ファイル名に、利用者 ID を含めて、分けてください）。

## 5. 確認の状況

- 確認済み: ローカルのテスト用サーバーで、`PUT`（文字列）、`GET`（文字列、バイナリ）、署名が違う場合・期限切れの場合に `403` で例外になること、`Content-Type` を指定した場合に、そのまま送られること。
- **未確認**: 実際の S3、Azure、Google Cloud に対する通し確認。クラウドごとの細かな違い（署名に含めるヘッダーなど）は、各クラウドの仕様を確認してください。
