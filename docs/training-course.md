# 新人向け演習コース案: 備品貸出アプリを作る（半日）

VJA を使って、プログラム未経験の新人が、半日で小さな業務アプリを1つ作る演習のコース案です。

> **この案は、まだ実施していません。** 時間配分や課題の難しさは、想定です。最初に実施した結果で、見直してください（11 節に、記録する項目を載せています）。

## 1. 想定

| 項目 | 内容 |
|---|---|
| 対象 | プログラム未経験の新人（Excel の基本操作ができる程度） |
| 期間 | 半日（約4時間。休憩を含む） |
| AI の接続 | クラウド API（低価格モデル）。1人あたりの費用は、数円程度が目安です（README のコスト試算を参照） |
| 人数 | 5〜10人。講師1人が、つまずいた人を順に助けられる人数 |
| 課題 | 備品貸出アプリ（画面2つ＋テーブル1つ） |

**ゴール**: 「画面を作り、AI でコードの下書きを作り、動かして、直す」という流れを、自分の手で1周すること。プログラムを書けるようになることは、ゴールではありません。

## 2. 講師の事前準備

- 各 PC に VJA を入れ、AI 接続設定を済ませます（ツールバー「AI設定」。クラウド API の場合は、API キーの入力）。**キーは、受講者に見せない・配らない運用にしてください**（講師が各 PC で入力するか、受講者の分を別々に発行します）。
- 課題の完成見本を、講師が先に1つ作っておきます。受講者の質問に答えやすくなります。
- 受講者に配る資料: この課題文（4 節）と、[ユーザーガイド](user-guide.md)、[VJA でのアプリ開発フロー](development-workflow.md)。

## 3. 時間割

| 時間 | 内容 | 節 |
|---|---|---|
| 0:00〜0:15 | 導入: VJA は何か、今日のゴール、完成見本のデモ | 5 |
| 0:15〜0:55 | 画面を作る: ウィジェットを手で置く → AI の下書きと比べる | 6 |
| 0:55〜1:25 | テーブルを作る | 7 |
| 1:25〜1:35 | 休憩 | |
| 1:35〜2:35 | 登録ボタンの処理を作る（日本語 → YAML → JS） | 8 |
| 2:35〜3:20 | 動かす、壊す、直す（実行エラーと「AI で修正」） | 9 |
| 3:20〜3:50 | 応用: 一覧と検索を足す | 10 |
| 3:50〜4:00 | まとめと振り返り | 11 |

## 4. 課題文（受講者に配る）

> 会社の備品（ノート PC、プロジェクターなど）の貸出を記録するアプリを作ります。
>
> 1. **登録画面**: 備品名、借りる人、貸出日を入力して、「登録」ボタンで保存します。
> 2. **一覧画面**: 登録した貸出の一覧を表示します。（応用）
>
> 入力が空のときは、登録せずにメッセージを出します。

## 5. 導入（15分）

- VJA の流れを、1枚で説明します（[開発フロー](development-workflow.md) の「生成 → 確認 → 必要なら直す → 次へ」）。
- 完成見本を、実際に動かして見せます。
- 伝えること: **AI は下書きを作る。確認して、直すのは人**。うまく動かないのは、普通のことです。
- 困ったら、ツールバーの「ヘルプ」で、日本語で質問できることを伝えます。

## 6. 画面を作る（40分）

1. メニュー［ファイル］→［新規プロジェクト］（またはツールバーの「新規」）で、新しいプロジェクトを作ります。
2. **手で配置**（20分）: ツールボックスから、ラベル、テキスト入力、ボタンをフォームに置き、「備品名」「借りる人」「貸出日」の入力欄と、「登録」ボタンを作ります。ウィジェットの名前（`txtItem` など）も、プロパティで付けます。
3. **AI の下書きと比べる**（15分）: 新しいフォームを追加して、「✨ YAMLドラフト」タブに、課題文の1を書いて、AI に画面を作らせます。手で作った画面と、見比べます。
4. 振り返り（5分）: どちらが速かったか。AI の画面で直したい所は、どこか。

ねらい: ウィジェットと名前、プロパティという、後で使う道具に触れること。AI の下書きは、直す前提だと分かること。

## 7. テーブルを作る（30分）

1. テーブル管理で、テーブル `equipment_loan`（貸出）を追加します。
2. 「✨ AI生成」の依頼文に、「備品名、借りる人、貸出日の3つの項目。備品名と借りる人は必須」のように書いて、列を生成します。
3. 生成された列（名前・型・必須）を、目で確認します。**列の名前は、後のコードが使うので、控えておきます。**

ねらい: AI の結果を確認する習慣をつけること（列名・型の確認）。

## 8. 登録ボタンの処理を作る（60分）

1. 「登録」ボタンの Click イベントを開き、「✨ YAMLドラフト」タブに、やりたいことを日本語で書きます。
   - 例: 「備品名、借りる人、貸出日の入力欄の値を取り、どれかが空ならメッセージを出して終わる。そうでなければ、テーブルに登録して、入力欄を空にし、完了メッセージを出す」
2. 「✨ YAMLドラフト生成」で、YAML を作ります。**この YAML を、読みます**（アクションの順番が、書いた通りか）。違う所は、YAML を直接直すか、依頼文を直して再生成します。
3. 「🤖 JSコード生成」で、JavaScript を作ります。
4. 生成された JavaScript を、講師と一緒に、1行ずつ読みます（`vja.widget.get`、`vja.db.execute`、`await` の意味を、1つずつ）。

ねらい: 「日本語 → YAML → コード」の流れと、コードを読むことの第一歩。**YAML は、AI への依頼であり、設計書でもある**ことを伝えます。

## 9. 動かす、壊す、直す（45分）

1. ツールバーの「実行」で、アプリを動かします。登録して、動作を確認します（DB に入ったか）。
2. **わざと壊す**（15分）: 例えば、JavaScript の中のテーブル名を、1文字変えて、もう一度動かします。
3. 実行エラーが出ると、ツールバーに「⚠ 実行エラー（件数）」が出ます。ここから一覧を開いて、エラーの内容を読みます。
4. 一覧の「🤖 AI で修正」で、修正案をもらい、**直った理由を、自分の言葉で説明**します。

ねらい: エラーは、普通の出来事で、読めば手がかりがあること。AI の修正案も、確認が必要なこと。

## 10. 応用: 一覧と検索を足す（30分）

- 一覧画面を追加して、登録した貸出を一覧表示します（データグリッド）。
- 時間が余った人は、「借りる人」で絞り込む検索を足します。
- 画面の追加や切り替えは、左側の「画面一覧」パネルで行います。

進度に差が出る部分です。早く終わった人には、検索を、遅れている人には、一覧の表示だけを、勧めます。

## 11. まとめと振り返り（10分）

講師から: 今日の流れ（画面 → テーブル → YAML → JS → 実行 → 直す）を、もう一度、通しで言葉にします。

**実施の記録（次回に向けた改善のため、毎回残してください）**

| 項目 | 記録する内容 |
|---|---|
| 完了 | 登録画面まで完成した人数、一覧まで完成した人数 |
| 時間 | 各節の実際の所要時間 |
| 最初の1回で動いた割合 | 8 節の JS 生成が、手直しなしで動いた人の割合 |
| つまずいた所 | 画面のどこで止まったか、講師が助けた内容 |
| 受講者の感想 | 「また使いたいか」「難しかった所」「分かりやすかった所」 |

## 12. 講師用: つまずきやすい点

- **ウィジェットの名前**: AI が作る名前と、自分で付けた名前が混ざって、コードが動かないことがあります。名前を、最初に確認する習慣をつけます。
- **YAML を読まずに、JS 生成へ進む**: 「YAML を、一度、声に出して読む」ことを促します。
- **AI の結果が毎回違う**: 同じ依頼でも、結果が違うのは普通です。気に入らなければ、依頼文を直して、再生成します。
- **エラーの文面が難しい**: 全文を理解させる必要はありません。「どのイベント」「何行目」だけを、読ませます。
- **API キーの扱い**: 画面を共有・撮影するときに、キーが映らないようにします。
