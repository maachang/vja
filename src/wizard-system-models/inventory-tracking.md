# 在庫・数量推移管理系

## 概要
品目（マスタ）に対して入庫・出庫のような増減イベントが積み重なり、現在の在庫数を追跡・表示する骨格。

## テーブル構成の型
品目マスタ＋履歴テーブルの2テーブル構成が基本形。現在庫数は履歴から都度集計するか、品目マスタ側に非正規化して持たせるかを、更新頻度・参照頻度で判断する。

```
例: 在庫管理
- items (品目マスタ)
  - id            INTEGER PRIMARY KEY
  - code          TEXT NOT NULL
  - name          TEXT NOT NULL
  - currentStock  INTEGER          -- 現在庫数（履歴から都度更新）
  - unit          TEXT             -- 単位（個・箱等）

- stock_moves (入出庫履歴)
  - id            INTEGER PRIMARY KEY
  - itemId        INTEGER NOT NULL  -- itemsへの参照
  - moveType      TEXT NOT NULL     -- "in"（入庫） / "out"（出庫）
  - quantity      INTEGER NOT NULL
  - movedAt       TEXT NOT NULL     -- 発生日時
  - note          TEXT
```

## 画面構成の骨格（重要）
- **品目一覧画面（1つ）**: 品目ごとの現在庫を一覧表示。検索条件（品目名・在庫少数のみ表示等）を持つ
- **入出庫登録画面（1つ）**: 品目選択＋入庫/出庫の区分＋数量を入力し登録。登録時に品目マスタの現在庫数量を増減させる処理を実装する
- **履歴確認**: 別画面ではなく、品目一覧の行から「履歴を見る」的な展開・モーダルで済ませることを優先する
- 在庫がマイナスにならないようなチェック（出庫時に現在庫を下回らないか）が必要な場合は、登録画面の保存処理内でバリデーションする

## AIが陥りやすい失敗（回避したい点）
- 現在庫数を履歴から都度集計せず、更新も忘れて数値が不整合になる
- 「入庫登録画面」「出庫登録画面」を別々に作ってしまう（区分値の選択で1画面にまとめられる）
- 品目マスタ管理画面と入出庫登録画面を無自覚に混在させ、責務があいまいになる
