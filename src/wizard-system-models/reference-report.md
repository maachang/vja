# 検索・照会/レポート系

## 概要
既存データの更新は行わず、複数条件で検索・絞り込みを行い、一覧・集計・グラフとして参照することだけが目的の骨格。他のパターン（マスタ管理系・伝票登録系等）で蓄積されたデータを、後から分析・確認する用途で使われることが多い。

## テーブル構成の型
新規にテーブルを持つ場合は少なく、既存の他パターンのテーブルをSELECTで参照する形が基本。集計結果を保存する必要がある場合のみ、集計結果テーブルを追加する。

```
例: 売上集計レポート（sales/sales_itemsを参照する想定）
- 新規テーブルは持たず、以下のようなSQLで都度集計する
  SELECT slipDate, SUM(amount) AS total
  FROM sales_items
  JOIN sales ON sales.id = sales_items.salesId
  WHERE slipDate BETWEEN ? AND ?
  GROUP BY slipDate
```

## 画面構成の骨格（重要）
- **1画面で完結させる**: 検索条件（期間・区分等）の入力欄＋検索ボタン＋結果の一覧表示（datagrid）または集計表示（数値・グラフ）
- 更新系のボタン（登録・編集・削除）は原則置かない。あくまで参照専用の画面である
- 集計方法が複数ある場合（日別/月別/担当者別等）は、selectBoxで切り替えられるようにし、画面自体は分割しない

## AIが陥りやすい失敗（回避したい点）
- 参照専用であるにも関わらず、登録・編集ボタンを混在させてしまう（責務があいまいになる）
- 検索条件を一切設けず、全件を都度集計してしまう（データ量が増えると実用に耐えない）
- 集計対象期間や区分ごとに別々の画面を作ってしまう（selectBoxでの切り替えで1画面にまとめられる）
