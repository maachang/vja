# 予約・スケジュール管理系

## 概要
会議室・設備のような対象に対して、開始〜終了の時間帯を予約し、重複を避けながら空き状況を確認する骨格。

## テーブル構成の型

```
例: 会議室予約
- resources (予約対象マスタ、例: 会議室)
  - id            INTEGER PRIMARY KEY
  - name          TEXT NOT NULL

- reservations (予約)
  - id            INTEGER PRIMARY KEY
  - resourceId    INTEGER NOT NULL  -- resourcesへの参照
  - reserverName  TEXT NOT NULL     -- 予約者名
  - startAt       TEXT NOT NULL     -- 開始日時
  - endAt         TEXT NOT NULL     -- 終了日時
  - purpose       TEXT              -- 用途・備考
```

## 画面構成の骨格（重要）
- **一覧・確認画面（1つ）**: 対象（会議室等）と日付を選んで、その日の予約状況を一覧表示する（時間帯の一覧、またはdatagridでの時系列表示）
- **登録画面（1つ）**: 対象・日付・開始/終了時刻・予約者名を入力。**保存前に、同一対象・同一時間帯に既存予約と重複していないかをDBに問い合わせてチェックする処理を必ず含める**（重複時はエラーメッセージで登録を中止）
- 変更・取消も、登録画面の流用または一覧からの直接操作で完結させ、別画面を増やさない

## AIが陥りやすい失敗（回避したい点）
- 重複チェックのロジックを省略し、単純に登録だけしてしまう（このパターンの骨格上、最も重要な処理）
- 開始・終了のどちらか一方しか持たない、または文字列比較だけで日時の前後判定を誤る実装にしてしまう
- 「予約一覧画面」「予約登録画面」「予約変更画面」「予約取消画面」を別々のFormとして作ってしまう
